# 公开快照状态 · 2026-11-01

本页区分已有代码、过去的实板观察和本次发布验证。不能据此认定所有模块已集成为可交付产品。

## 硬件

- 目标板：NiceMCU-T5-2.8IPS，240 × 320 显示，ST7789 / CST816。
- 已有显示、触摸、Wi-Fi 恢复与本地演示固件的板测记录。
- 公开源码默认 `BREATHON_PRESENTATION_ONLY=1`；它不会因为出现通话界面就打开真实语音。
- 实时语音候选 1.0.22 曾在本地准备，尚未由本任务烧录；其他 BLE 任务的板测仍独立进行。本仓库没有操作串口或更新板子。
- 麦克风队列溢出与网络停顿曾出现，仍需结合实板长时间通话验证，不能声称全双工验收完成。

## BLE 和数据来源

板端 BLE 帧与 App 解析器都在仓库内，当前 App 仍实例化 `MockDevice`。

**特别注意：当前板端 BLE 生成模拟丙酮数值，但帧的 mock 标记未可靠体现这一来源。** 不应因接收到了 BLE 数据帧，就把它标成真实传感器数据。真实 App 传输接入前需要统一 C 与 Rust 协议的数据来源标记，并增加对应测试。本次源码发布保留了这一已知限制，没有把它包装成传感器已接入。

## App 与模型

浏览器 / Tauri 页面、SQLite 记录与估算规则已存在。App 聊天页当前是本地模板；真实 OpenAI Realtime 网关属于另一条板端语音链路。

模型返回过 PCM 音频，仅能证明上游链路曾响应。用户尚未确认持续、清晰的真实板端语音交互；声音播放、麦克风收音、打断与回声需单独验收。

## 下一轮验收

1. 完成 BLE 真实传输层，保持模拟 / 传感器来源的明确标记。

4. 传感器接入后再验证标定、单位、采样与数据质量。
5. App 与数据 API 的真实同步、移动端打包属于后续工作。
